## 2. 최종 계산 규칙

작업자 `i`의 현재 출동 시작 시각을 `t`, 같은 날의 이전 출동 `j`의 작업 후 Borg를 `B_j`, 완료 시각을 `e_j`, 작업자별 회복 반감기를 `h_i`라고 할 때 누적피로도는 다음과 같다.

```text
누적피로도_i(t) = Σ [B_j × 0.5^((t - e_j) / h_i)]
```

- 현재 출동의 Borg는 계산에 포함하지 않는다.
- 하루의 첫 출동은 무조건 `누적피로도=0`, `회복시간=0`이다.
- 이후 출동의 회복시간은 같은 날 직전 출동 완료 시각부터 현재 출동 시작 시각까지의 분이다.
- 날짜가 바뀌면 이전 날짜의 출동은 누적하지 않는다.
- 기존 응답과의 호환성을 위해 `recovered_daily_load`는 누적피로도의 별칭으로 유지한다.

### 개인별 회복계수

반감기가 짧을수록 회복이 빠르다. `k = ln(2) / 반감기(분)`이다.

| 회복 순위 | 작업자 | 반감기(분) | 분당 계수 k | 60분 후 잔존율 |
|---:|---|---:|---:|---:|
| 1 | 김경언 | 60 | 0.01155245 | 0.5000 |
| 2 | 최현 | 90 | 0.00770164 | 0.6300 |
| 3 | 강경래 | 120 | 0.00577623 | 0.7071 |
| 4 | 정하람 | 180 | 0.00385082 | 0.7937 |
| 5 | 박우민 | 360 | 0.00192541 | 0.8909 |

따라서 요청한 `김경언 > 최현 > 강경래 > 정하람 >> 박우민` 회복 속도 순서가 보장된다. 이 값은 현재 운영 가정이며 생리학적 실측 계수는 아니다.

## 3. 데이터 출처와 가정 데이터 구분

Excel에서 참여 여부가 1이고 측정 단계가 `작업후`이며 Borg가 존재하는 행만 사용한 뒤, `근로학생 + 최종출동ID`로 묶어 총 118개 학습 표본을 만들었다.

| 작업자 | 표본 수 | 데이터 구분 | 회복 반감기(분) |
|---|---:|---|---:|
| 최현 | 23 | 실제 기록 응답(`recorded_response`) | 90 |
| 김경언 | 24 | 실제 기록 응답(`recorded_response`) | 60 |
| 강경래 | 23 | 가정 데이터(`synthetic_assumption`) | 120 |
| 박우민 | 24 | 가정 데이터(`synthetic_assumption`) | 360 |
| 정하람 | 24 | 가정 데이터(`synthetic_assumption`) | 180 |

나머지 세 명을 가정 데이터로 분류한 이유는 원본 파일의 설계상 실제 응답자로 지정된 사람이 최현·김경언 두 명뿐이고, 강경래·박우민·정하람의 Borg 값은 개인 실측 응답으로 확정할 근거가 없기 때문이다. 값 자체를 삭제하지 않고 모델 학습에는 사용하되, 실제 응답처럼 오해하지 않도록 출처를 `synthetic_assumption`으로 보존했다. 이 분류는 예측 결과의 신뢰도를 해석할 때 반드시 함께 봐야 한다.

## 4. 구현된 전체 흐름

```text
Excel 업로드/읽기
  → 참여 작업자의 작업후 행 선별
  → 작업자·출동별 118개 표본 생성
  → 개인 반감기로 누적피로도·회복시간 계산/검증
  → 전체 모델 1개 + 개인 모델 5개 학습
  → Supabase 계정과 개인 모델 연결
  → 출동 전 Borg 예측
  → 작업 완료 및 실제 Borg 저장
  → 작업자 상태·인력 추천에 동일 누적피로도 사용
  → 실제 응답이 쌓이면 운영 데이터로 재학습
```

모델 피처는 다음 9개로 통일했다.

```text

item_count, labor_load, team_size,

```

## 7. 단일 출동 E2E 검증

자동화 테스트에서 최현 계정으로 다음 흐름을 검증했다.

1. 첫 출동: 09:00 시작, 09:30 완료, 실제 Borg 3.5 저장
2. 첫 출동 직전 피처: 누적피로도 0, 회복시간 0
3. 두 번째 출동: 10:00 시작
4. 두 번째 출동 직전 피처: `3.5 × 0.5^(30/90) = 2.778`, 회복시간 30분
5. 예측 응답, 작업자 상태 조회, 인력 추천이 모두 같은 누적피로도 값을 사용함을 확인

Excel의 최현 출동 6을 한 건 홀드아웃한 추가 진단에서는 실제 Borg 4.0, 예측 6.3, 절대오차 2.3이었다. 기능 연결은 정상이나 이 한 건의 오차는 모델 정확도가 아직 충분히 검증되지 않았음을 보여준다.

## 11. 최종 판단

요청한 누적피로도·회복시간 계산, 회복 순서, 5개 개인화 계정과 모델, API 연계, 단일 출동 테스트, Excel 결과물, Supabase 반영까지 하나의 흐름으로 완결했다. 현재 남은 것은 제품 운영 단계의 두 가지다.

1. 변경된 서버 코드를 실제 호스팅 환경에 배포하는 작업
2. 특히 가정 데이터로 시작한 세 명의 실제 Borg 응답을 수집해 모델 정확도를 재검증하는 작업

이 두 항목은 현재 구현 누락이 아니라 배포 권한과 실제 운영 데이터가 필요한 후속 단계다.
